# ARENA 미션 프롬프트 (고정 — 모든 모델 공통)

이 파일 전문이 모델 입력입니다. 모델마다 바꾸지 마십시오. 코딩 성능을 모델끼리
비교하는 것이 목적이므로, 프롬프트와 허용 정보가 모두 동일해야 합니다.

---

## 지시

당신은 모바일 로봇 제어 코드를 작성하는 엔지니어입니다. 이 프롬프트와 함께
`base_carter_run.py` 전문이 주어집니다. 그 파일은 수정하지 말고, 사본으로
`<모델 본인 이름>_carter_run.py` 를 만들어 사본의 `[EDIT REGION]` ~
`[END EDIT REGION]` 블록만 수정해 미션을 통과시키십시오.
`<모델 본인 이름>` 에는 당신의 실제 모델 이름을 넣습니다(예: `claude`, `qwen3_4b`).
파일 시스템에 접근할 수 없으면 **수정한 파일 전문을 그대로 출력**하십시오.

## 규칙

1. `[EDIT REGION]` 블록 밖은 한 글자도 바꾸지 마십시오. docstring, `MISSION`,
   `START`, `GOAL`, 마지막 3줄 모두 그대로 둡니다.
2. `controller(t, pose, env) -> (v, w, done)` 계약을 지키십시오. 매 1/60 s 호출되며
   `pose` 는 (x, y, yaw) 월드 좌표, `v` 는 전진 속도 [m/s], `w` 는 yaw 각속도 [rad/s],
   `done=True` 면 미션을 종료하고 채점받습니다.
3. 센서: `env.raycast_scan()` 은 현재 헤딩 기준 전방 180° 를 61빔으로 훑어
   `[(방위각 rad, 거리 m), ...]` 를 반환합니다. 거리 6.0 은 무히트입니다. 인자는
   base 의 docstring 에 적힌 것만 씁니다.
4. import 추가 금지 — 이미 import 된 `math` 만 사용하십시오.
5. 난수·벽시계·파일 입출력·스레드에 의존하지 말고 결정론적으로 제어하십시오.
   같은 입력에 항상 같은 출력이어야 합니다.
6. 참고할 수 있는 것은 **이 프롬프트와 `base_carter_run.py` 두 개뿐**입니다.
   저장소의 다른 파일(`layout.json`, `arena_map.json`, `sim2d.py`, `REPORT.md`,
   `*.yaml`, `levels/`, `levels_zero2level/` 의 solution·prompted 코드 등)은
   열어 보지 마십시오. 그 안에 배치 의도와 해답이 들어 있어 비교가 무의미해집니다.
7. 시뮬레이터를 직접 실행하지 마십시오. 실행과 채점은 채점자가 합니다.
   다만 채점자가 Isaac Sim 에서 실행한 결과는 아래 '추가 허용 사항 2' 처럼 적극적으로 활용하십시오.
8. 결과물은 파일 하나입니다.

## 추가 허용 사항 (프롬프트 A-1)

아래 두 가지는 규칙 위반이 아니며, 적극적으로 활용할 것을 권장합니다.

### 1. 경유점(waypoint)을 직접 찍어 경로를 만들어도 됩니다

- 출발점에서 목표까지 가는 경로를 경유점 목록으로 직접 설계해도 됩니다. 경유점 개수에는
  제한이 없으니, 필요하면 촘촘하게 찍으십시오.
- 경유점 좌표는 `MISSION` 에 적힌 `START`, `GOAL`, `boxes` 의 값으로 계산해도 되고,
  숫자로 직접 적어(하드코딩) 넣어도 됩니다.
- 예를 들어 경유점을 차례로 따라가다가 한 경유점에 충분히 가까워지면 다음 경유점으로
  넘어가고, 마지막에 `GOAL` 위치에 도착하면 `GOAL` 의 yaw 로 제자리에서 돌아 정렬한 뒤
  멈추는 방식으로 제어할 수 있습니다.
- 경유점을 따라가면서 `env.raycast_scan()` 으로 앞쪽 장애물을 확인해 속도를 줄이거나
  피하는 반응형 제어를 함께 써도 됩니다.
- 지금 몇 번째 경유점을 향하는지처럼 호출 사이에 기억할 값은 `[EDIT REGION]` 안의 전역
  변수나 함수 속성에 저장해도 됩니다. 이는 규칙 5 의 결정론과 충돌하지 않습니다.

### 2. Isaac Sim 을 적극적으로 활용해도 됩니다

- 제출한 코드는 매번 채점자가 실제 Isaac Sim(PhysX 물리 엔진)에서 실행하며, 통과하지
  못하면 그 실행의 판정 결과를 돌려받습니다. 판정 결과에는 최종 위치와 방향
  (`final_pose`), 목표까지 거리, 충돌 횟수, 부딪힌 물체의 이름(`collision_partners`),
  첫 충돌 시각(`first_collision_t`) 등이 들어 있습니다. 각 제출을 Isaac Sim 에서의 시험
  주행으로 여기고, 그 결과로 경로와 제어를 적극적으로 고치십시오.
- `env.raycast_scan()` 은 Isaac Sim 의 PhysX 광선 검사를 그대로 호출합니다. base docstring
  에 적힌 인자 `n_beams`, `fov_deg`, `z`, `max_range` 는 원하는 값으로 바꿔도 되며, 한 번의
  `controller()` 호출 안에서 설정을 달리해 여러 번 불러도 됩니다.
- `pose` 는 Isaac Sim 이 매 단계 알려 주는 로봇의 정확한 위치와 방향이므로 그대로 믿고
  써도 됩니다.

## 미션

창고 전체가 실험장입니다. 로봇은 남서쪽 모서리 `START` 자세로 스폰되고, 반대편
북동쪽 모서리의 `GOAL` 까지 약 34 m 를 주행해야 합니다. 사이에는 바닥에 놓인
정적 박스 14개가 있고, 그 위치·크기·높이는 base 의 `MISSION["boxes"]` 에
주어집니다(x, y = 중심, width = X 방향, depth = Y 방향, height = 높이, 단위 m).
창고에는 벽·기둥·선반·지게차 같은 고정 구조물도 있습니다.

목표 위치에 도달해 `GOAL` 의 yaw 로 정렬한 뒤 정지하십시오.

## 성공 조건 (고정 하네스가 판정)

base 의 `MISSION` 에 적힌 값으로 판정합니다.

| 항목 | 기준 |
|---|---|
| 최종 위치 | `GOAL` 에서 `position_tolerance_m` (0.75 m) 이내 |
| 최종 yaw | \|yaw 오차\| ≤ `yaw_tolerance_rad` (0.26 rad) |
| 충돌 | 0회 — 박스, 지게차, 서쪽 선반 모두 집계됩니다 |
| 시간 | `timeout_s` (120 s) 안에 정지 |

충돌이 시작되면 하네스가 5초 뒤 실행을 중단합니다.
실행 속도(벽시계)·코드 길이·주석 언어는 판정에 쓰지 않습니다.
