B-5-19 a2 분석과 외곽 명령 필터 검토 (2026-11-06)

결론: a2의 M1 접촉은 choose_command 우회가 아니다. 이미 검사된 출력을 보존하는 외곽 필터로는 같은 실패를 구제하지 못했다. 과거 코드 중 명령이 바뀐 B514 세 건도 CPU 미션 판정은 모두 FAIL이었다.

a2 1회차는 시험 없이 제출했다. Isaac 채점은 601.0s, 접촉 0, 최종 거리 13.2842m로 FAIL이다. 선택 로그 1,200개 중 stop_safe가 1,127개이고 지도 정지 경고는 18회다.
경로 생성은 처음 6점(margin .50), 이후 18회 모두 2점(.70)이었다. 최종 저장 자세에서 원 planner를 재실행하면 시작 격자 중심 여유 .46098m < .70m 때문에 None을 반환한다. 실패 후 직선 fallback을 재사용하고 재검사하지 않는 분기가 원인이다. 그 직선은 check_path min_gap_map=-.25m, first_bad_segment=0이다. 반올림된 최종 자세의 재현이며 과거 모든 재계획을 재생한 것은 아니다.
a2 2회차 시험 6개는 모두 /World/arena_mover_00 접촉으로 FAIL이다. 첫 접촉은 시뮬레이션 8.700~8.867s이며, 요청에 적힌 약 36s는 도구 실행의 벽시계 시간이다.

6개 시험 모두 sim_seconds를 생략해 한도는 600s였다. 최종 답은 한 물리적 줄의 JSON wrapper 안에 개행과 EDIT 마커가 escaped된 code 문자열로 들어갔다. splice=false, static_dq("EDIT REGION 표시가 없거나 깨졌습니다.")로 두 번째 Isaac 채점은 없다. 내부 문자열을 별도로 디코딩한 코드는 어느 시험 코드와도 다르며 실행되지 않았다.
실행된 7개 controller의 모든 반환 v,w는 choose_command 결과다. target은 월드 좌표의 경유점 또는 GOAL 두 성분이고, 속도는 m/s와 rad/s, 각도는 atan2로 정규화한 rad이며, 잘못된 단위나 형식은 발견되지 않았다. 객체 검사 horizon은 기본 3s다.
2회차는 지도 경로를 버리고 GOAL을 직접 추종한다. 시험02는 관측 중심과 목표선의 거리, 03은 예측 중심의 근접 거리, 04는 전방 선분, 05/06은 전방 부채꼴 조건으로 후진 입력을 수동 선택한다. 02의 robot_on_line은 항상 True인 분기도 있다. 움직이는 물체의 정답 위치를 넣은 분기는 없다.
시험01부터 공통으로 chosen=stop이면 지도 때문인지 확인하지 않고 choose_command(0,.4,target)를 다시 부른다. 반환은 여전히 두 번째 chooser 결과다. 접촉 전 5s의 저장 DBG에서는 이 정지 분기의 실제 실행을 확인할 수 없으므로 접촉의 단독 원인으로 단정하지 않는다.
대표 시험01은 t=5.0s부터 map_clearance_object_gap(공동 안전 후보 없음), t=8.0s부터 follow/stop TTC=0이다. 위험을 예측했는데도 all-unsafe 후보 선택 후 접촉했다. DBG는 0.5s 구간 첫 호출만 남기므로 최종 모터 명령이나 두 번째 호출을 확정할 수 없고, 원시 관측점도 없어 실제 추적 오차는 복원할 수 없다.

외곽 필터는 analysis/b519_shield_support.py에만 구현했다. 원 저장 코드의 helper와 EDIT를 유지하고, 직접 반환된 명령만 별도 v8 chooser로 검사한다. B514의 직접 check_motion 선택은 새 chooser의 검증 기록이 없으므로 추가 검사 대상이다.
이미 검사된 출력은 같은 controller 호출, 실제 시각/자세, 관측 snapshot, 반환 pair가 일치하는 원 chooser 호출 기록으로 판별한다. 시뮬레이션은 그 결과를 재사용한다. 글자 그대로 한 번 더 호출하려면 선택된 pair가 아니라 기록한 원 nominal/target/horizon을 같은 관측에서 재실행해야 한다.
선택된 pair를 새 nominal로 재입력하는 단순 이중 호출은 불변이 아니다. 실제 v8 단위 반례에서 (.3,0)→(1,0)→(.5,0)으로 바뀌었다. 원 인자 재실행은 (1,0)을 보존했다. 틱/자세/관측 불일치와 반환 후 변경도 검사한 단위 점검은 20/20 PASS다. 이는 Python 악성 코드 격리가 아니라 제어 호출 계약이다.
모르는 target은 ahead=(x,y)+sign(v)×max(1,3|v|)×(cos(yaw),sin(yaw))와 GOAL[:2]를 비교했다. v=0이면 전방 1m다. ahead는 곡선 명령의 종점이 아니라 직선 방향점이다. 정확한 경유점 전달이 우선이며, 임시 fallback은 ahead로 제안하되 아래 결과에서 어느 대체값도 성공을 보장하지 않았다.

CPU 범위는 B514~19의 실행 가능한 실패 채점 15개와 현재 a2 시험 6개다. static_dq 5개는 제외했다. B519 a3는 읽거나 실행하지 않았다.
원 버전(v2/v4/v5/v6/v7/v8) 내부 chooser와 tracker를 유지하고 바깥쪽만 v8로 했다. 실제 관측 points만 전달했으며 정답 물체 위치는 센서 생성/접촉 채점 외에 사용하지 않았다.
고정 v1, seed=51916, 60Hz, 가속도 제한 2m/s²와 2.68rad/s², 센서 10Hz/지연 .1s/잡음 .01m, 600s 한도로 비교했다. done도 원본 그대로 두고 MISSION 위치 .75m/각도 .26rad/무접촉으로 별도 채점했다.

start_zone은 CPU의 M1, center는 다른 이동 물체다. B514 a0 t1 GOAL은 접촉을 피했지만 원 done 시 거리 .90469m로 FAIL이다. B514 a1 t2도 접촉은 피했으나 두 방식 모두 목표 미도달이다. 명령이 달라진 3개에서 FAIL→PASS는 0개다.
a2 시험01/02/03/04/06의 CPU 접촉은 8.8167s, 시험05는 8.7333s다. 전부 현재 틱 chooser 결과만 반환하므로 보호 장치 뒤에도 그대로다. 실제 세 모드를 실행한 시험01은 529틱 전부 검증/명령 변경 0이고 접촉 직전에도 chooser가 고른 후진(-.2,0)이 그대로 전달됐다.
CPU는 원 Isaac 센서/차체 동역학의 재생이 아니다. 실제 실패했던 B515 a0 t1과 B516 a3 t1이 CPU 기준선부터 PASS이고, B518 RRT도 고정 난수 경로라 실제 경로와 다르다. 첫 접촉에 종료하며 Isaac의 접촉 후 대기/물리 settle도 생략한다. 이 차이를 외곽 필터 개선으로 세지 않았다.
초기 B519 a2 t1 GOAL 실행은 575.9s에 NumPy any TypeError가 났다. 원 기록을 archive한 뒤 동일 조건 단독 재시도는 600s까지 정상 완료했고 기준선과 hash도 같다. 초기 예외의 원인은 미확정이며 재시도 감사 기록에 남겼다.

고칠 제안은 다음 3개다.

1. 재계획 경로는 매번 check_path를 통과해야 채택한다. 확대 여유 때문에 현재 시작 셀이 거절되면 지도에서 유효 셀까지의 연결을 검사하고, 검증되지 않은 직선 fallback을 재사용하지 않는다.
2. 지도 경유점의 추종 입력을 유지하고 센서 중심 기반 수동 후진/정지 후 재호출을 없앤다. 최종 반환 명령, 원 입력/target, 선택 이유와 관측점을 기록해 all-unsafe 선택과 실제 가속/접촉의 차이를 검증한다.
3. 외곽 필터를 도입한다면 현재 틱의 원 호출 기록과 경유점 전달을 계약으로 삼고 검증 결과를 보존한다. 기록 없는 명령의 추가 검사는 우회 방지용이며, 이미 검사된 위험 명령과 경로 정체를 고치는 기능으로 취급하지 않는다.
