## 모델이 거부 줄을 보고도 고치지 못한 과정
- 1회차 뒤 채점 피드백에는 DBG가 없었다. 모델은 정체 결과로 visibility graph 실패를 추정했다.
- 2회차의 각 시험 뒤에는 실제 `plan_reject` t=0/10/590 s 세 줄이 모델에 전달됐다.
- c03 응답의 reasoning은 다른 여유의 거부 줄이 없으므로 c=0.4에서 채택됐을 것이라고 추정하고 lookahead를 고쳤다.
- 실제 v12는 같은 이유를 10 s에 한 번만 출력해 한 계획 배치의 c=0.45/0.4/0.35 거부를 숨겼다.
  로그 부재는 채택 증거가 아니었지만, 모든 시도의 결과와 실제 채택 상태를 명시하는 요약이 없었다.
- 기존 프롬프트에도 이웃 선분 검사, 지도 여유를 지키는 단순화와 `validate_plan()` 지시가 있었다.
  그러나 원 코드 9개 모두 `validate_plan()`/`check_path()`를 호출하지 않았다. 잘못된 채택 추정 뒤 lookahead를 바꾸고,
  선분 검증 대신 격자 크기, 무검증 단순화와 수동 경유점을 시도했다.

## 수정 방향과 검증 범위
- 수용 여유를 일괄 낮추지 않는다. 시험 1 원 A*에 이웃 선분 여유 검사 하나만 추가한 분석용 대조는 네 여유 모두 승인됐다.
  원본은 변경하지 않았고, 같은 엄격도에서 유효 경로가 존재함을 확인한 지도 검사이며 실제 주행 성공 증명은 아니다.
- v13은 수용 기준을 유지하고 전체 계획 배치의 각 여유 결과와 `accepted/no_path/retained` 상태를 한 줄로 알린다.
- B525 지시는 `no_path`일 때 planner부터 고치고, 이웃 연결과 단순화 선분을 검사한 뒤 `validate_plan()` 결과를 확인하도록 보강한다.
- 참고 구현 60개와 v1, 기존 오류 6종 및 원 a1의 이웃 검사 누락을 흉내 낸 일곱째 조건으로 재검증한다.
