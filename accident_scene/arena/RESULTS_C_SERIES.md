# C 계열 실험 결과 (2026-11-15 ~ 11-18, 서버 fractal)

역할을 나눈 LLM 에이전트(코더·검토·분석)가 Nova Carter 경유점 제어기를 고쳐, 무작위로 놓인 이동 장애물
(`ARENA_MOVERS=v1r`)을 피해 목표에 도달하게 만드는 실험이다. 역할별 모델만 바꿔 가며 같은 과제를 돌렸다.

## 과제와 통과 기준

- 출발 코드: A-4 경유점 추종(속도 5배, 센서 미사용). `results/turns/prompt_c2_turn0/start_block.py`
- 기반 파일 `base_carter_run_c2.py`, 과제 프롬프트 `PROMPT_C2.md`, 분석 프롬프트 `PROMPT_C1_ANALYST.md`, 검토 프롬프트 `PROMPT_C1_REVIEWER.md`
- 한 턴 = 코더 → 검토 → 정적 검사 → 새 무작위 배치로 Isaac 실행(최대 10회) → 분석. 분석의 진단이 다음 턴 코더의 입력
- **통과 = 한 턴에서 10회 모두 통과하고 시뮬 시간 합계가 600 s 이하** (실행당 평균 60 s)
- 턴 예산 600 s 를 실행들이 나눠 쓰고(실행별 한도 = 남은 예산), 3회 실패하면 그 턴의 실행을 끝낸다. 정지 60 s·진행 부족 90 s 면 실행 중단

## 실험 도중 바꾼 것 (계열 비교 시 감안)

- C-2 35턴부터 분석 프롬프트에 "진단 전에 먼저 답할 것"(가정 점검, 접근법 계열, 구조가 다른 후보 2~3개) 추가. 이전 판은 `PROMPT_C1_ANALYST_until_turn34.md`
- C-3 2턴 뒤 과제 프롬프트에 통과 기준(턴 예산 600 s, 실행당 평균 60 s) 명시. 이전 판은 `PROMPT_C2_until_c3turn2.md`
- C-3 진행 중 분석 입력에 코드의 DBG 출력(실행별 처음 10줄 + 마지막 50줄, 줄당 300자)과 잘린 양 통계 추가
- C-5 부터 vLLM 분석 모델은 입력이 문맥 한도를 넘으면 DBG 줄 수를 줄이는 장치 추가(C-5~C-7b 에서 한 번도 작동하지 않음)
- C-7b 와 C-8 에만(`c1_cycle.FACT_SERIES`): 분석 입력에 (1) 이번 턴 실행 집계 - 10개 중 몇 개를 실행했고 왜 나머지를 못 했는지, 통과 실행의 평균 시간과 필요한 60 s, 통과 기준 충족 여부, (2) 검토 담당이 진단에 대해 적은 의문을 넣는다. C-7 의 14·25턴에 분석이 7/7, 8/8 을 완료로 읽은 것이 계기다.
- C-7b 3턴: 하네스의 근거 검사가 "stall_abort." 의 마침표를 숫자로 읽어 죽었다. 고친 뒤 3턴의 분석만 같은 입력으로 다시 받았다(원래 답은 `*_raw_crashed_BAD.json`).

## 하네스에 남은 틈 (미적용)

- 코더의 답 형식(바꿀 최상위 정의만 냄)으로는 정의를 지울 수 없다. 분석이 "제거하라"고 해도 코드가 남는다.
- 목표 근처에서 조금씩 움직이며 끝나지 않는 실행을 끊는 규칙이 없어, 한 실행이 턴 예산 600 s 를 다 쓸 수 있다(C-7b 17턴).
- 분석이 후보를 하나만 내거나 `failure_mode` 에 정해지지 않은 값을 적어도 걸러지지 않는다.
- 이전 턴 요약표에 충돌 상대와 위치가 없어, 같은 지점의 반복 충돌을 턴을 넘어 알아보기 어렵다.
