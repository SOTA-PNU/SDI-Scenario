## A-1: 허용 문구만 더함

원문은 한 글자도 지우거나 고치지 않았고 두 곳에 덧붙였다.

1. 규칙 7 끝에 한 문장을 더했다.
   > 다만 채점자가 Isaac Sim 에서 실행한 결과는 아래 '추가 허용 사항 2' 처럼 적극적으로 활용하십시오.
2. 미션 절 앞에 '추가 허용 사항 (프롬프트 A-1)' 절을 두었다. "아래 두 가지는 규칙 위반이 아니며, 적극적으로 활용할 것을 권장합니다."
   - **경유점 허용.** 개수 제한이 없다. `MISSION` 의 START, GOAL, boxes 로 계산해도 되고 하드코딩해도 된다. 차례로 따라가다 GOAL 에서 GOAL yaw 로 정렬하고 멈추는 예를 들었다. `env.raycast_scan()` 으로 반응형 제어를 함께 써도 된다. 몇 번째 경유점인지 같은 상태는 EDIT REGION 안의 전역 변수나 함수 속성에 저장해도 되고, 규칙 5 의 결정론과 충돌하지 않는다.
   - **Isaac Sim 활용 허용.** 매 제출은 채점자가 Isaac Sim(PhysX)에서 실제로 돌리는 시험 주행이고, 실패하면 판정 결과(final_pose, 목표까지 거리, 충돌 수, collision_partners, first_collision_t 등)를 돌려받으니 그것으로 적극적으로 고치라고 했다. `raycast_scan` 의 네 인자는 값을 바꿔도 되고 한 번의 `controller()` 호출에서 여러 번 불러도 된다. `pose` 는 믿어도 된다.

실행 방식은 A 와 같다. 모델이 답을 내면 채점자가 Isaac 에서 돌리고, 실패하면 결과 JSON(obstacle 블록 제외)을 다음 메시지로 준다. 모델이 직접 Isaac 을 돌리는 수단은 없다.

## A-2: 경유점 지시, 시간 제한 삭제, Isaac Sim 시험 도구

1. **제목**을 바꿨다.
2. **지시 절**에 직접 지시와 작업 순서를 더했다.
   > 이번 과제는 **경유점(waypoint)을 찍고 그 경로를 따라 주행하는 방식으로** 푸십시오. 그리고 답을 내기 전에 **`run_isaac_sim` 도구로 Isaac Sim 에서 직접 주행시켜 검증**하십시오.

   순서는 경유점 설계, 추종과 GOAL yaw 정렬, 시험 주행, 원인을 찾아 고치고 다시 주행, `"verdict": "pass"` 가 나온 코드 제출의 다섯 단계다.
3. **규칙 7 을 바꿨다.** A 의 "시뮬레이터를 직접 실행하지 마십시오. 실행과 채점은 채점자가 합니다." 를 "시뮬레이터는 아래 `run_isaac_sim` 도구로만 실행합니다. 최종 채점은 채점자가 같은 하네스로 따로 합니다." 로 바꿨다.
4. **새 절 '경유점 주행 방법'.** A-1 의 경유점 허용 내용을 옮기고 세 가지를 더했다. 상자가 차지하는 범위가 x 방향으로 `x ± width/2`, y 방향으로 `y ± depth/2` 라는 것, 가장자리에서 여유를 두라는 것, 상자 표에 없는 벽, 기둥, 선반, 지게차는 `collision_partners` 로 확인하라는 것이다.
5. **새 절 'Isaac Sim 검증 도구 `run_isaac_sim`'.**
   - 실행 환경: 이 실험을 운영하는 GPU 서버(RTX PRO 6000 1장), Isaac Sim 4.5.0 화면 없음, PhysX, 1/60 s, 장면, ROS 2 `/cmd_vel` 지연, `pose` 는 정확, `carter-run accident_scene/arena/<실행 파일>` 로 실행, 30초에서 몇 분, 같은 코드는 같은 결과, 시험 주행은 판정에 들어가지 않음.
   - 입력: `code`(파일 전문이나 EDIT REGION 블록), `sim_seconds`(10–600 s, 기본 600).
   - 돌려받는 결과: `static_check`, `result`(최종 채점 피드백과 같은 형식), `trajectory`(최대 80개), `harness_events`, `controller_output`(`print("DBG", ...)` 줄의 처음 40줄과 마지막 40줄), `runtime_error`, `tests_left`.
   - 한도: 회차당 10번.
6. **새 절 '제출'.** 도구 호출 없이 낸 답이 그 회차의 제출이고, 실패하면 판정 결과를 받고 다음 회차로 간다.
7. **성공 조건.** 표의 "시간: `timeout_s` (120 s) 안에 정지" 행을 지우고 다음 문단을 넣었다.
   > 시간 제한은 없습니다. 빨리 도착할 필요가 없으니 충돌하지 않는 속도로 천천히 주행해도 됩니다. 다만 실행이 끝없이 이어지지 않도록 하네스가 시뮬레이션 시각 `timeout_s` (600 s)에서 실행을 멈추므로, 그 전에 목표에 도착해 정렬하고 `done=True` 를 돌려주십시오.

**base 의 차이 (`base_carter_run_a2.py`).** 두 줄만 다르다. `MISSION` 의 `timeout_s` 가 120.0 에서 600.0 이 되었고, docstring 의 `timeout_s` 설명이 "sim-time budget" 에서 "run cutoff in sim time - a safety stop so a run cannot go on forever, not a pass criterion (there is no time limit)" 가 되었다. 모델에게는 프롬프트가 부르는 이름 그대로 `base_carter_run.py` 로 보인다.

**실행 방식 (`agent_loop.py`).** 도구 정의(`run_isaac_sim(code, sim_seconds)`)를 요청의 `tools` 로 보낸다. NPU 서버의 기본 도구 호출 기능을 쓴다. 모델이 도구를 부르면 공식 채점과 같은 경로(carter-run, 직렬 실행, 로그 보관)로 이 서버의 Isaac 에서 돌리고 결과 JSON 을 돌려준다. 회차당 10번까지이고, 회차 상한은 2 다. 실행 중에 두 가지를 보강했다. 서버가 해석하지 못해 버린 도구 호출을 생성 원문에서 복원하는 기능과, Isaac 동시 실행을 막는 잠금 래퍼(`carter_run_locked.sh`)다(REPORT.md 실험 11 실행 중 기록).

   - 규칙 7 은 A-2 와 같다.
4. **새 절 '검증된 경유점 경로'.**
   - 경유점 `_WAYPOINTS = [(-4.7, -7.3), (-3.7, 5.1), (0.7, 11.3), (2.3, 15.1), (8.0, 16.5)]`.
   - 창고 고정 구조물 지도와 `MISSION["boxes"]` 를 합친 지도에서 로봇 중심이 모든 장애물에서 1.1 m 이상 떨어지도록 계산했다는 설명.
   - 확인 주행 수치: 약 62초에 목표 원 진입, 67초에 종료, 충돌 0회, 최종 거리 0.23 m, yaw 오차 0.05 rad, 로봇 중심의 최소 여유 1.1 m.

5. **새 절 '추종 방법'.** 거리와 방향 오차 `e` 를 매 호출 계산하고, 마지막이 아닌 경유점은 0.35 m 안에서 다음으로 넘어간다. `|e| > 0.35` rad 이면 제자리 회전(`v = 0`, `w = clamp(1.5e, ±0.8)`), 아니면 전진(`v = min(0.6, 0.5·dist + 0.1)`). GOAL 0.25 m 안에서 정렬 단계(`w = clamp(1.5e, ±0.6)`)에 들어가 머물고, `|e| < 0.05` rad 에서 `(0, 0, True)`. 명령 지연 때문에 속도와 이득을 크게 올리지 말라는 주의.

## A-4: 경로만 빼고 직접 설계하게 함

A-3 에서 다음만 바꿨다. 추종 방법 절은 A-3 과 글자까지 같다.

1. **제목과 머리 문단.** "다만 경로는 당신이 직접 설계해야 합니다." 를 더했다.
2. **지시 절.** "출발점에서 목표까지 장애물을 피해 가는 경유점 경로를 직접 설계하고, 아래 추종 방법으로 그 경로를 따라가는 제어기를 작성하는 것입니다." 와, 추종 방법은 장애물과 충분히 떨어진 경로에서 통과를 확인했다는 설명. 작업 순서의 첫 단계가 "`MISSION["boxes"]` 와 고정 구조물을 보고 경유점 목록을 설계" 로 바뀌었다.
3. **'검증된 경유점 경로' 절을 '경유점 설계' 절로 바꿨다.** 경유점 목록과 확인 주행 수치, "경유점을 바꾸거나 더하지 마십시오" 가 빠지고 다음이 들어갔다.
   - 좌표는 계산해도 되고 하드코딩해도 된다. 개수 제한이 없으니 모서리에서 촘촘하게. 마지막 경유점은 GOAL.
   - 상자 범위 `x ± width/2`, `y ± depth/2`, 고정 구조물도 장애물이다.
   - 경유점 사이의 직선 구간 전체가 장애물에서 떨어져 있어야 한다.
   - 확인 주행에서는 로봇 중심이 모든 장애물에서 1.1 m 이상 떨어진 경로를 따라갔다.
