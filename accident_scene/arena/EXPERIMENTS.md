# EXPERIMENTS.md — 본론 실험 지시서 (rev.2)

수신: GPU 서버 에이전트 (NPU 서버 접속 가능)
관련 문서: [`PAPER.md`](PAPER.md), [`BENCHMARK.md`](BENCHMARK.md), [`TURNS.md`](TURNS.md)
목적: 대한임베디드공학회 단편(4쪽). **우수발표논문상 도전.**

이 문서는 **무엇을 왜 재는지**를 먼저 적고 절차를 뒤에 적는다. 절차만 읽고 실행하지 말 것.
어느 주장을 위한 숫자인지 모르면 쓸 수 없는 데이터가 나온다.

**섹션 순서 = 실행 순서다.** 위에서부터 차례로 한다. 시간이 부족하면 뒤에서부터 버린다.

## 0. 이 논문의 주장 구조

`PAPER.md` 의 기여 순서를 뒤집고, **처방 검증을 주장에 추가했다.** 진단만 하는 논문과
진단 후 처방까지 보이는 논문은 다른 종류의 논문이다.

### 서론의 논지

정적 검사는 60/60 통과했다. 텍스트 채점기라면 전부 "돌아간다"고 판정할 코드다. 그런데
물리 하네스에 올리면 60/60 실패한다. 자연스러운 해법은 생성 → 시뮬레이터 검증 → 피드백
→ 재생성 루프다. 이 논문은 그 루프를 실제로 붙여 보고, **왜 그것이 원리적으로 이 실패를
고칠 수 없는지**를 측정한 뒤, **무엇이면 고쳐지는지**를 보인다.

### 본론의 주장 (우선순위 = 지면 순서 = 실행 순서)

| # | 주장 | 실험 |
|---|---|---|
| **C1** | 실패 원인은 정보 부족이 아니라 **명세 독해 실패**다. 박스 높이(0.18~0.25 m)와 스캔 평면(z=0.35 m)이 둘 다 프롬프트에 있었고, 트랙 A 30건은 그것을 읽을 권한이 있었으며 30/30 실패했다. | **실험 1** |
| **C2** | 물리를 **외부 모델로 외화**하면 달라진다. 컨텍스트 안에서 숫자 두 개를 교차 참조하는 것은 실패하지만, 그 관계를 실행 가능한 검사로 내보내면 포착된다. | **실험 2** |
| **C3** | 따라서 결과 피드백 루프는 수렴하지 않는다. 루프는 없던 정보를 공급하는 장치인데, 빠진 것이 정보가 아니었다. 12실행 93턴 통과 1건. | 기존 데이터 + **실험 3** |
| **C4** | 루프가 하는 일은 수렴이 아니라 **오라클 회피**다. 충돌을 0으로 만드는 과정이 저평면 장애물에서 물러나는 과정과 같다. | **실험 3·4** |
| **C5** | 피드백을 더 줘도 수렴하지 않는다. 풍부함은 실패 **양상**을 바꿀 뿐이다. | **실험 5** (버릴 수 있음) |

**C1 이 척추, C2 가 상을 가른다.** C3 는 C1 의 따름정리로 서술한다 — 관측이 아니라
예측으로 쓰면 "턴을 더 주면 되지 않나"라는 반박이 애초에 성립하지 않는다.

### 결론의 논지

빠진 것은 검증이 아니라 명세와 물리 사이의 다리다. 실험 2 가 그 다리를 놓는 두 가지 방식 
— 에이전트가 스스로 물리 모델을 구성하게 하기, 또는 명세 대조를 기계 검증 가능한 형태로 제공하기 — 
을 각각 실증한다.

### 용어 변경 — 전 저장소 적용

`trap` / "함정" 을 **저평면 장애물(sub-plane obstacle)** 로 바꾼다. 인위적 함정이라는
비판을 초대하는 명명이다. 코드 식별자(`trap_exposure_m`, `trap_collision`)는 호환을 위해
그대로 두되, 새 산출물의 사람이 읽는 라벨과 `REPORT.md` 본문은 새 용어를 쓴다.

논문에는 방어 문단을 넣는다: 정보를 전부 공개했으므로 은닉이 아니고, 고정 평면 스캔
아래의 낮은 장애물은 실제 AMR 운용의 표준적 사고 유형(팔레트 날, 도크 립, 케이블
트레이, 턱)이며, 참조선 실행이 통과했으므로 불가능한 과제가 아니다.

### 환경 버전 (2026-10-08 추가)

- **v1** — 실험 1–9 의 환경. 박스 04·05·06·13 이 0.25·0.20·0.18·0.20 m 로 스캔 평면(0.35 m) 아래.
  원본 `env_v1/`. 분석 스크립트와 논문 그림이 읽는 `layout.json` 은 v1 그대로 둔다.
- **v2** — 2026-10-08 부터. 위 네 박스의 height 만 0.6 m(로봇의 가장 높은 라이다 XT32 0.526 m 보다 높게).
  `base_carter_run.py` · `nova_carter_warehouse_arena.yaml` 이 v2, 분석용 표는 `layout_v2.json`.
  나머지(위치·크기·출발·목표·판정·하네스·PROMPT)는 v1 과 같다.
- v1 과 v2 결과를 한 표나 한 비율로 합치지 않는다. v2 에는 스캔 평면 아래 박스가 없다.
- 모델 입력(첫 메시지 = PROMPT.md + base)도 바뀐다. v1 6,961자(sha16 92630b632e138139), v2 6,959자(sha16 795a7ed41355262c).
- 하네스의 `raycast_scan()` 은 PhysX 가 처음 돌려준 충돌면에서 멈춘다. 그 면이 가장 가까운 면이
  아닐 수 있다(v1 표본 빔 2.59 %, v2 3.49 %; `analysis/scan_order_v1.log`, `_v2.log`).
  하네스는 고치지 않았다. 고칠지는 사용자 결정이다.

## 1. 절대 하지 말 것

위반하면 기존 60건 + 93턴이 비교 불가가 되어 논문이 사라진다.

1. **하네스·프롬프트·베이스를 수정하지 않는다.** `levels/common/carter_env.py`,
   `PROMPT.md`, `PROMPT_B.md`, `base_carter_run.py`, `arena_harness.py` 는 읽기 전용.
   오라클 임계값(0.75 m / 0.26 rad / 0 충돌 / 120 s)과 스캔 평면 z=0.35 m 은 상수다.
   버그를 발견해도 고치지 말고 `REPORT.md` 에 보고만 한다.
2. **기존 결과 파일에 쓰지 않는다.** `results/runs.csv`, `results/turns/cap8/**`,
   `results/generated/serving.csv` 는 불변. 새 산출물은 §6 경로에만 쓴다.
3. **Isaac 을 병렬로 돌리지 않는다.** `carter-run` 가드를 우회하지 않는다.
4. **cap8 과 cap30 을 풀링하지 않는다.** 턴 상한이 다르면 다른 프로토콜이다.
5. **트랙 A 와 트랙 B 를 수치 비교하지 않는다.** 재는 능력이 다르다.
6. **실험 2·5 는 GPU 에서만 돌린다.** NPU 라우터는 seed 로 재현되지 않는다(같은 seed
   1002 로 출력 상이 기록 있음). 재현성이 전제인 실험을 NPU 에서 돌리면 무의미하다.
7. **백엔드 간 `reasoning_tokens` 를 비교하지 않는다.** furiosa-llm 370~1,900 대 vLLM 0
   은 회계 차이지 모델 차이가 아니다.
8. **허용치 근처 값은 단독 보고 금지.** 최종 거리가 0.65~0.75 m 구간이면 하네스의 두
   타이밍 모드 폭을 함께 적는다.
9. **사후 합리화 금지.** 각 실험은 실행 **전에** 예상 결과를 `REPORT.md` 에 적고 시작한다.
   예상과 다르면 그 사실을 남긴다. 예상을 지우고 다시 쓰지 않는다.
10. **실험 2a 의 추가 문장이 정답을 누설하지 않아야 한다.** 누설 감사를 반드시 거친다.
    누설된 문장으로 얻은 통과는 결과가 아니라 오염이다.

## 실험 1 — 명세 독해 계측 (C1, 최우선)

**목적.** "정보는 프롬프트에 다 있었다"를 주장에서 측정으로 바꾼다. 지금 `PAPER.md` 에는
단정으로만 적혀 있어 심사위원이 검증할 수 없다. 이 표 하나가 논문의 척추다.

**대상.** 트랙 A 의 모든 생성물 — 1회차 30건 + 턴 프로토콜의 모든 A 트랙 응답. 원문은
`results/turns/*_raw.json` 과 1회차 생성물 저장 위치. 추론 트레이스(reasoning content)가
저장돼 있으면 **포함**하고, 없으면 그 사실을 보고한다.

**절차.** 각 응답 텍스트(코드 + 주석 + 산문 + 추론 트레이스)를 4단계로 분류한다.
자동 탐지 후 **전수 수동 확인**할 것. n 이 100 단위라 가능하고, 핵심 증거라 자동 분류만
으로는 방어가 안 된다.

| 단계 | 정의 | 탐지 신호 (출발점, 정규식은 보수적으로) |
|---|---|---|
| L0 | 둘 다 언급 없음 | 아래 어느 것도 없음 |
| L1 | 한쪽만 언급 | 높이 값(`0.18`~`0.25`, `height`) **또는** 스캔 평면(`0.35`, `z=`, `raycast`, `scan plane`) |
| L2 | 둘 다 언급, 연결 없음 | 양쪽 다 등장하나 비교·귀결 문장 없음 |
| L3 | 교차 참조하여 귀결 도출 | "낮아서 스캔에 안 잡힌다", "평면 아래", "보이지 않는다" 류의 명시적 추론 |

L3 이면서 실패한 건은 **별도로 뽑아 사례로 쓴다.** 추론까지 했는데 코드에 반영하지 못한
경우는 C1 보다 강한 증거다.

**이 분류기를 재사용한다.** 실험 2a 의 출력에 같은 척도를 적용해 단계 분포가 이동하는지
본다. 그러므로 분류 로직을 `analysis/spec_tier.py` 로 모듈화하고 CLI 로 임의 응답 집합에
적용 가능하게 만들 것.

**출력.** `results/analysis/spec_reading.csv`
```
run_id, model, accel, track, turn_idx, tier, mentions_height, mentions_plane,
has_inference, verdict, evidence_quote, quote_source
```
`evidence_quote` 는 판정 근거 원문 조각(80자 이내), `quote_source` 는
`code|comment|prose|reasoning`. 집계표(단계 × verdict 교차)도 함께.

**예상 결과(실행 전 기록).** L0/L1 다수, L2 소수, L3 0~2건. 만약 L2·L3 가 과반이면
C1 을 약화하지 말고 **"읽었으나 코드로 옮기지 못했다"로 전환**한다. 그쪽이 더 흥미로운
결과다.

## 실험 2 — 처방 검증: 물리의 외화 (C2, 상을 가르는 실험)

**왜 중요한가.** 진단만 하는 논문은 "그래서 뭘 하라는 것이냐"에 답하지 못한다. 참조선
실행이 자체 2D 재현기를 만들어 통과했다는 감사 기록이 있다 — 성공의 결정적 행동이
"더 열심히 추론하기"가 아니라 **물리를 외부 모델로 외화하기**였다는 가설. 최소 규모로
확인한다. **2a 가 본 실험, 2b 가 보조이자 안전망이다. 둘 다 한다.**

### 2a — 외부 물리 모델 유도

**설계.** 트랙 A, gpt-oss-120b, GPU / vLLM 0.29.0, n=5. 샘플링·seed 를 1회차 트랙 A
gpt-oss GPU 5건과 **동일하게** 맞춘다. 그 5건이 대조군이고, 이미 존재하므로 새로 돌릴
필요가 없다. 쌍체 비교가 된다.

`PROMPT.md` 에 **한 문장만** 추가한다. 다른 부분은 한 글자도 건드리지 않는다.

후보 문장:
> 컨트롤러를 작성하기 전에, 주어진 장애물 명세와 센서 명세를 대조하는 2D 기하 검사
> 코드를 먼저 작성해 실행하고, 그 결과를 컨트롤러 설계의 근거로 삼으라.

**누설 감사 — 실행 전 필수.** 추가 문장이 다음 중 무엇도 포함하지 않아야 한다.
(ㄱ) 박스 높이 수치, (ㄴ) 스캔 평면 수치나 `z=0.35`, (ㄷ) "낮은 장애물", "스캔에 안
잡힌다" 같은 귀결, (ㄹ) 특정 박스 번호. 문장 전문과 감사 통과 여부를 `REPORT.md` 에
그대로 기록한다. **무엇을 하라(외화)는 말해도 되고, 무엇을 발견할 것인지는 말하면 안 된다.**

**측정 항목 — 통과 수가 전부가 아니다.**
1. 통과 수 (대조 5건 vs 처치 5건)
2. `trap_exposure_m` — 저평면 장애물에 시험받았는지 자체
3. **실험 1 의 단계 분포 이동** — 처치군 응답에 `spec_tier.py` 적용. L0/L1 에서 L2/L3 로
   이동하면 통과가 0이어도 결과다
4. 모델이 실제로 검사 코드를 작성했는지 (작성률)
5. 작성한 검사가 저평면 박스를 식별했는지 (식별률)

**4·5 가 핵심이다.** "지시했으나 안 했다", "했으나 못 찾았다", "찾았으나 컨트롤러에
반영 못 했다" 는 서로 완전히 다른 결론이고, 어느 쪽이든 논문에 쓸 수 있다.

**출력.** `results/prescription/externalize/` — 생성물, `raw.json`, `request.json`,
채점 결과, `tier.csv`, 그리고 모델이 작성한 검사 코드를 별도 추출한 `checks/`.

**예상 결과(실행 전 기록).** 작성률 5/5, 식별률 2~4/5, 통과 0~2/5. 통과가 0이어도
단계 분포가 이동하면 C2 는 성립한다.

### 2b — 기계 검증 검사의 소급 적용

**목적.** 결정적이라 반드시 결과가 나온다. 2a 가 전부 실패해도 논문의 처방 절이 빈손이
되지 않는다. 그리고 임베디드 청중에게는 도구 기여로 읽힌다.

**구현.** `analysis/spec_consistency_check.py` — `MISSION` 표에서 박스 높이를 파싱하고
`carter_env.py` 의 스캔 평면 상수를 읽어, 윗면이 평면보다 낮은 박스 집합 S 를 만든다.
제출된 컨트롤러에 대해 다음을 검사한다.
- S 의 박스가 지도상 장애물로 취급되는가 (좌표·반경이 코드에 반영)
- 또는 스캔 평면이 S 의 최저 높이 아래로 낮춰졌는가
- 둘 다 아니면 **사전 경고**

**소급 적용.** 기존 60건 전부 + 93턴 전부. Isaac 채점 **이전에** 몇 건이 걸러졌을지를
센다. 실제 실패와의 일치율(경고 ∩ `trap_collision`)도 함께.

**정직하게 적을 것.** 이 검사는 정답을 알고 작성한 것이므로 일반 탐지기가 아니다.
보이는 것은 "이 실패가 기계적으로 검증 가능한 종류였다"이지 "우리가 범용 도구를
만들었다"가 아니다. 이 문장을 논문에 그대로 쓴다.

**출력.** `results/prescription/static_check/retro.csv` — run_id, warned(bool),
actual_failure_type, agreement.

## 발표 자산 (실험 3 전에 착수)

## 실험 3 — 노출 거리 × 충돌 궤적 (C3·C4, 그림 3)

**목적.** 그림 3 을 "턴별 충돌/거리"에서 **충돌 수와 저평면 장애물 노출 거리를 한 평면에
겹친 그림**으로 재설계한다. 세 양상(정지 수렴 / 진동 / 오라클 순차 폐쇄)이 이 평면에서
서로 다른 모양으로 갈리는지 본다.

**선행 확인 — 먼저 이것부터 보고.** `results/turns/cap8/turns.csv` 에 `trap_exposure_m`
이 턴 단위로 있는가? `score_runs.py` 는 실행 단위로 계산하는데 `turn_summary.py` 가
턴별로 옮기고 있는지 확인한다.

- 있으면 바로 출력으로.
- 없고 궤적 로그가 턴별로 저장돼 있으면 역산한다.
- 궤적이 없으면 보존된 컨트롤러를 Isaac 으로 재채점해 궤적을 얻는다. 하네스는 8/8 동일
  판정이 확인돼 있어 유효하다. 다만 93턴 재채점은 비싸므로 **wall-clock 을 추정해
  보고하고 승인을 기다린다.**

**출력.** `results/analysis/turn_trace.csv`
```
run_id, track, accel, model, turn_idx, verdict, failure_type, collision_count,
trap_exposure_m, final_dist_m, yaw_err_rad, elapsed_s, phenotype
```
`phenotype` ∈ `stall_converge | oscillate | sequential_closure | other`. 분류 기준을
`REPORT.md` 에 **규칙으로 명문화**하고 사후에 눈으로 붙이지 않는다. 제안: 마지막 3턴의
`collision_count` 가 모두 0이고 `final_dist_m` 가 단조 증가 또는 정체면 `stall_converge`,
실패 유형이 2턴 주기로 반복되면 `oscillate`, 오라클 위반 개수가 단조 감소하면
`sequential_closure`.

**플롯.** `figs/fig3_exposure_collision.svg` — x축 turn_idx, 왼쪽 y축 `collision_count`,
오른쪽 y축 `trap_exposure_m`, phenotype 별 3패널. 통과한 a4 실행 강조. 벡터, 88 mm 폭 확인.

## 실험 4 — 오라클 회피 정량화 (C4)

**목적.** "충돌이 0으로 가는 동안 노출 거리가 커진다"를 수치로.

**절차.** 실행별로 turn_idx 에 대한 `collision_count` 와 `trap_exposure_m` 의 추세를 각각
Kendall tau 로 계산하고, 두 부호가 반대인(충돌↓·노출↑) 실행 수를 센다.

**n=12 다.** 추론 통계를 쓰지 말고 기술 통계로만 보고한다. p-value 를 붙이지 않는다.
"12실행 중 k개에서 관측"이 정직한 서술이다.

**출력.** `results/analysis/oracle_avoidance.csv` — run_id, tau_collision, tau_exposure,
opposite_sign. 가장 선명한 실행 1건의 턴별 수치를 본문 예시용으로 뽑아둘 것.

## 실험 5 — 피드백 풍부함 절제 (C5, 시간 없으면 버린다)

**왜 필요한가.** 기존 `PAPER.md` 의 기여 ③은 트랙 A 와 B 를 비교했는데, 두 트랙은
피드백 풍부함과 좌표 열람 허용 여부가 **동시에** 다르다. 교란된 비교라 그대로 쓸 수 없다.
트랙 A 내부에서 피드백만 바꿔 단일 변수로 다시 잰다. **못 하면 C5 를 논문에서 뺀다.**
빼도 논문은 성립한다.

**설계 — 쌍체.**

| | A-lean | A-rich |
|---|---|---|
| 프롬프트 | `PROMPT.md` (동일) | `PROMPT.md` (동일) |
| 모델 / 가속기 / 샘플링 | gpt-oss-120b, GPU, temp 0.7, top_p 0.95, seed 1000+i | 동일 |
| 턴 상한 | 8 | 8 |
| **피드백** | verdict, final_dist_m, yaw_err_rad, collision_count, elapsed_s **만** | 위 + 충돌 프림 이름, 충돌 시각, 충돌 시점 로봇 자세 |

seed 고정이므로 **1턴 생성물이 두 조건에서 동일해야 한다.** 분기는 첫 피드백에서만
발생한다. 시작 전 1턴 코드의 sha256 일치를 확인해 기록하고, **다르면 중단 후 보고한다**
— vLLM 재현성이 깨진 것이므로 설계 전제가 무너진다. 가능하면 기존 cap8 의 1턴
생성물을 재사용해 포크한다.

5 seed × 2 조건 × 최대 8턴 = 최대 80턴.

**`mask_feedback.py` 를 쓰지 않는다.** 그것은 트랙 B 좌표 마스킹이다. 여기 필요한 것은
필드 선택이므로 `feedback_profile.py` 에 `lean`/`rich` 프로파일을 두고 `turn_loop.py` 에
인자로 넘긴다. 기존 기본 동작을 바꾸지 않는다.

**주요 지표.** 통과 수는 부차적이다(양쪽 0일 가능성이 높다). 볼 것은 턴별 phenotype,
노출 거리 궤적, 같은 실패 유형 반복 횟수, 정적 실격 발생률.

**출력.** `results/turns/ablation_feedback/` — `turns.csv`(스키마는 `turn_trace.csv` +
`condition` 열), `*_raw.json`, `*_request.json`, `*_transcript.md`.

**예상 결과(실행 전 기록).** 양쪽 통과 0. rich 가 진동 비율 높고 lean 이 정지 수렴 비율
높다. 맞으면 "더 준 쪽이 더 나쁘다"가 아니라 **"피드백 풍부함은 실패 양상을 바꾸지만
수렴시키지 못한다"**로 쓴다. 후자가 데이터가 지지하는 범위이고 방어하기 쉽다.

## 7. 막혔을 때

- **오라클을 바꾸면 통과할 것 같을 때** → 바꾸지 않는다. 그것이 이 논문의 결과다.
- **실험 2a 에서 한 문장만 더 주면 될 것 같을 때** → 주지 않는다. 누설 감사를 통과한
  문장 하나가 전부다. 더 주고 싶으면 별도 조건으로 만들고 그렇게 보고한다.
- **기존 결과와 새 결과가 불일치할 때** → 기존을 수정하지 말고 둘 다 보고한다.
  `static_screen.py` 정규식 버그를 고치고 31/31 재검사한 선례처럼 적는다.
- **시간이 부족할 때** → 섹션 순서를 지킨다. 실험 1·2 와 발표 자산만 끝나도 논문은
  성립한다. 실험 5 를 먼저 버리고, 그다음 실험 6 을 버린다.
