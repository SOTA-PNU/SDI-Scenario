# ARENA 미션 프롬프트 A-3 (검증된 경유점 경로와 Isaac Sim 검증)

이 파일 전문이 모델 입력입니다. 이 프롬프트는 앞선 실험(A, A-1, A-2)에서 얻은 정보를
바탕으로 미션 통과를 돕도록 만든 안내판입니다.

---

## 지시

당신은 모바일 로봇 제어 코드를 작성하는 엔지니어입니다. 이 프롬프트와 함께
`base_carter_run.py` 전문이 주어집니다. 그 파일은 수정하지 말고, 사본으로
`<모델 본인 이름>_carter_run.py` 를 만들어 사본의 `[EDIT REGION]` ~
`[END EDIT REGION]` 블록만 수정해 미션을 통과시키십시오.
`<모델 본인 이름>` 에는 당신의 실제 모델 이름을 넣습니다(예: `claude`, `qwen3_4b`).
파일 시스템에 접근할 수 없으면 **수정한 파일 전문을 그대로 출력**하십시오.

이번 과제는 아래 **'검증된 경유점 경로'를 그대로 따라가는 제어기**를 작성하는 것입니다.
그 경로와 추종 방법은 이 서버의 Isaac Sim 에서 충돌 없이 목표에 도착해 통과하는 것을
미리 확인했습니다. 다음 순서로 작업하십시오.

1. 아래 경유점 목록과 추종 방법대로 `controller()` 를 작성합니다.
2. `run_isaac_sim` 으로 주행시켜 결과를 확인합니다.
3. 실패했다면 결과의 `collision_partners`, `first_collision_t`, `trajectory`,
   `controller_output` 을 보고 원인을 찾아 고친 뒤 다시 주행시킵니다.
4. **시험 주행에서 `"verdict": "pass"` 를 확인하기 전에는 제출하지 마십시오.** 시험 횟수가
   남아 있으면 계속 고쳐서 시험하십시오.
5. pass 가 나온 그 코드를 그대로 최종 답으로 제출합니다.

## 규칙

1. `[EDIT REGION]` 블록 밖은 한 글자도 바꾸지 마십시오. docstring, `MISSION`,
   `START`, `GOAL`, 마지막 3줄 모두 그대로 둡니다.
2. `controller(t, pose, env) -> (v, w, done)` 계약을 지키십시오. 매 1/60 s 호출되며
   `pose` 는 (x, y, yaw) 월드 좌표, `v` 는 전진 속도 [m/s], `w` 는 yaw 각속도 [rad/s],
   `done=True` 면 미션을 종료하고 채점받습니다.
3. 센서: `env.raycast_scan()` 은 현재 헤딩 기준 전방 180° 를 61빔으로 훑어
   `[(방위각 rad, 거리 m), ...]` 를 반환합니다. 거리 6.0 은 무히트입니다. 인자는
   base 의 docstring 에 적힌 것만 씁니다. 이번 과제에서는 쓰지 않아도 됩니다.
4. import 추가 금지 — 이미 import 된 `math` 만 사용하십시오.
5. 난수·벽시계·파일 입출력·스레드에 의존하지 말고 결정론적으로 제어하십시오.
   같은 입력에 항상 같은 출력이어야 합니다. 몇 번째 경유점을 향하는지 같은 상태는
   `[EDIT REGION]` 안의 전역 변수나 함수 속성에 저장해도 됩니다.
6. 참고할 수 있는 것은 **이 프롬프트와 `base_carter_run.py` 두 개뿐**입니다.
7. 시뮬레이터는 아래 `run_isaac_sim` 도구로만 실행합니다. 최종 채점은 채점자가 같은
   하네스로 따로 합니다.
8. 결과물은 파일 하나입니다.

## 검증된 경유점 경로

출발점 `START` (-9.0, -10.8) 에서 목표 `GOAL` (8.0, 16.5) 까지 다음 경유점을 차례로 지나갑니다.
마지막 경유점이 `GOAL` 입니다.

```
_WAYPOINTS = [(-4.7, -7.3), (-3.7, 5.1), (0.7, 11.3), (2.3, 15.1), (8.0, 16.5)]
```

- 이 경로는 창고의 고정 구조물 지도와 `MISSION["boxes"]` 를 합친 지도에서, 로봇 중심이 모든
  장애물에서 1.1 m 이상 떨어지도록 계산했습니다. 경유점 사이를 곧게 따라가면 충돌하지 않습니다.
- 이 경로와 아래 추종 방법으로 한 확인 주행은 약 62초에 목표 원에 들어가 67초에 끝났고, 충돌은
  0회, 최종 거리 0.23 m, yaw 오차 0.05 rad 였습니다. 주행 내내 로봇 중심은 장애물에서 1.1 m 이상
  떨어져 있었습니다.
- 경유점을 바꾸거나 더하지 마십시오. 시험 주행에서 충돌이 나면 경로보다 먼저 추종 방법을
  의심하십시오(제자리 회전 없이 크게 돌며 전진하면 경로에서 벗어납니다).

## 추종 방법 (이 값으로 통과를 확인했습니다)

- 지금 향하는 경유점까지의 거리 `dist` 와 방향 오차 `e = wrap(atan2(ty - y, tx - x) - yaw)` 를
  매 호출 계산합니다. `wrap` 은 각도를 [-π, π] 로 접는 함수입니다(`math.atan2(math.sin(a), math.cos(a))`).
- 마지막이 아닌 경유점은 `dist < 0.35` m 가 되면 다음 경유점으로 넘어갑니다.
- `|e| > 0.35` rad 이면 **제자리에서 회전**합니다: `v = 0`, `w = clamp(1.5 * e, -0.8, 0.8)`.
- 그렇지 않으면 전진합니다: `v = min(0.6, 0.5 * dist + 0.1)`, `w = clamp(1.5 * e, -0.8, 0.8)`.
- 마지막 경유점(`GOAL`)에서 `dist < 0.25` m 가 되면 그때부터는 전진하지 않고 제자리에서
  `GOAL` 의 yaw 로 돌립니다: `e = wrap(GOAL[2] - yaw)`, `w = clamp(1.5 * e, -0.6, 0.6)`, `v = 0`.
  한번 이 정렬 단계에 들어가면 계속 그 단계에 머뭅니다.
- 정렬 단계에서 `|e| < 0.05` rad 가 되면 `(0.0, 0.0, True)` 를 돌려줘 미션을 끝냅니다.
- 명령은 ROS 2 `/cmd_vel` 로 전달되어 반영이 조금 늦습니다. 위 속도와 이득보다 크게 올리면
  경로에서 벗어나거나 정렬에서 흔들릴 수 있습니다.

## 지금까지의 주행에서 알게 된 것

- 출발점에서 목표 쪽으로 곧장 가면 상자 00, 01, 02 에 부딪힙니다. 위 경로는 상자 00 의
  동쪽, 상자 01 과 02 의 서쪽을 지나갑니다.
- 상자 표에 없는 고정 구조물이 있습니다(축에 나란한 경계 상자, 단위 m).
  - 지게차 `Forklift_01`: x -9.59 ~ -6.10, y -3.45 ~ -2.23
  - 지게차 `Forklift`: x 1.84 ~ 5.44, y -3.43 ~ -0.55
  - 서쪽 선반과 그 위의 물건: x -10.33 ~ -8.33, y -3.55 ~ 11.80
  - 북서쪽의 고정 물체: x -7.25 ~ -5.00, y 12.75 ~ 14.50
  - 벽의 안쪽 면: 대략 x = -10.2 와 9.5, y = -12.0 과 18.0
- 앞선 실험의 모델은 시험 주행에서 실패를 보고도 다시 시험하지 않고 바로 제출해 실패했습니다.
  pass 를 확인하기 전에는 제출하지 마십시오.
- 앞선 실험에서 도구 호출의 `arguments` JSON 이 깨져 실행되지 못한 일이 있었습니다(문자열 끝에
  `]` 가 하나 더 붙음). `code` 에는 `[EDIT REGION]` 블록만 넣고, JSON 문자열 안의 줄바꿈과
  따옴표가 올바르게 escape 되었는지 확인하십시오.

## Isaac Sim 검증 도구 `run_isaac_sim`

이 대화에서 당신은 `run_isaac_sim` 도구를 호출할 수 있습니다. 호출하면 최종 채점과 같은
서버, 같은 장면, 같은 하네스에서 코드를 실제로 주행시키고 그 결과를 돌려줍니다.

**실행 환경**

- 실행 위치는 이 실험을 운영하는 GPU 서버(NVIDIA RTX PRO 6000 1장)입니다. Isaac Sim
  4.5.0 을 화면 없이 실행하며, 물리 엔진은 PhysX, 시뮬레이션 간격은 1/60 s 입니다.
- 장면은 NVIDIA 창고에 `MISSION["boxes"]` 의 상자 14개를 놓고 Nova Carter 를 `START`
  자세에 세운 것입니다.
- `controller()` 가 돌려준 `(v, w)` 는 ROS 2 `/cmd_vel` 로 로봇에 전달되므로 반영까지
  약간의 지연이 있습니다. `pose` 는 Isaac Sim 이 매 단계 알려 주는 정확한 값입니다.
- 도구는 받은 코드를 `base_carter_run.py` 의 `[EDIT REGION]` 에 넣어 실행 파일을 만들고,
  서버에서 `carter-run accident_scene/arena/<실행 파일>` 로 실행합니다. 한 번 실행에 부팅을
  포함해 30초에서 몇 분이 걸립니다.
- 같은 코드는 같은 결과를 냅니다. 시험 주행은 모두 기록되지만 판정에는 들어가지 않습니다.

**입력**

- `code` (필수): `[EDIT REGION]` 블록만 넣으십시오(파일 전문도 받지만 길어서 JSON 이 깨지기
  쉽습니다). 블록을 주면 도구가 base 에 끼워 넣습니다.
- `sim_seconds` (선택): 이번 시험에서 돌릴 최대 시뮬레이션 시간으로 10–600 s, 기본 600 s
  입니다. 위 경로는 보통 2분 안에 끝나므로 200 정도면 충분합니다.

**돌려받는 결과 (JSON)**

- `static_check`: 실행 전 정적 검사 결과입니다. 규칙 1 위반이나 문법 오류가 있으면 실행하지
  않고 이유를 알려 줍니다.
- `result`: 판정 결과로, 최종 채점 피드백과 형식이 같습니다. `verdict`, 판정 항목별 결과,
  `final_pose`, `final_dist_m`, `final_yaw_err_rad`, `collision_count`, `collision_partners`
  (부딪힌 물체의 prim 경로), `first_collision_t`, `time_to_goal_s` 등이 들어 있습니다.
- `trajectory`: 실제 주행 궤적에서 고르게 뽑은 `[t, x, y, yaw]` 최대 80개입니다.
- `harness_events`: 목표 원 진입, 충돌 뒤 중단, 시간 종료 같은 하네스 기록입니다.
- `controller_output`: `controller()` 안에서 `print("DBG", ...)` 처럼 줄 맨 앞에 `DBG` 를
  붙여 출력한 줄입니다. 처음 40줄과 마지막 40줄만 돌려주므로 경유점이 바뀔 때처럼 필요한
  때만 출력하십시오. 최종 제출 코드에 남아 있어도 판정에는 영향이 없습니다.
- `runtime_error`: `controller()` 가 예외를 던졌으면 그 내용입니다.
- `tests_left`: 이번 회차에 남은 시험 주행 횟수입니다.

**한도**: 한 회차에 시험 주행은 최대 10번입니다.

## 제출

시험 주행에서 pass 를 확인했으면 도구를 더 부르지 말고, 그 코드로 만든 최종 파일
(`<모델 본인 이름>_carter_run.py` 전문 또는 `[EDIT REGION]` 블록)을 답으로 출력하십시오.
도구 호출 없이 낸 답이 그 회차의 제출이며, 채점자가 같은 하네스로 실행해 판정합니다.
통과하지 못하면 판정 결과를 받고 다음 회차에서 고쳐 다시 제출합니다.

## 미션

창고 전체가 실험장입니다. 로봇은 남서쪽 모서리 `START` 자세로 스폰되고, 반대편
북동쪽 모서리의 `GOAL` 까지 약 34 m 를 주행해야 합니다. 사이에는 바닥에 놓인
정적 박스 14개가 있고, 그 위치·크기·높이는 base 의 `MISSION["boxes"]` 에
주어집니다(x, y = 중심, width = X 방향, depth = Y 방향, height = 높이, 단위 m).
창고에는 벽·기둥·선반·지게차 같은 고정 구조물도 있습니다.

목표 위치에 도달해 `GOAL` 의 yaw 로 정렬한 뒤 정지하십시오.

## 성공 조건 (고정 하네스가 판정)

base 의 `MISSION` 에 적힌 값으로 판정합니다.

| 항목 | 기준 |
|---|---|
| 최종 위치 | `GOAL` 에서 `position_tolerance_m` (0.75 m) 이내 |
| 최종 yaw | \|yaw 오차\| ≤ `yaw_tolerance_rad` (0.26 rad) |
| 충돌 | 0회 — 박스, 지게차, 서쪽 선반 모두 집계됩니다 |

시간 제한은 없습니다. 빨리 도착할 필요가 없으니 충돌하지 않는 속도로 천천히 주행해도
됩니다. 다만 실행이 끝없이 이어지지 않도록 하네스가 시뮬레이션 시각 `timeout_s`
(600 s)에서 실행을 멈추므로, 그 전에 목표에 도착해 정렬하고 `done=True` 를 돌려주십시오.

충돌이 시작되면 하네스가 5초 뒤 실행을 중단합니다.
실행 속도(벽시계)·코드 길이·주석 언어는 판정에 쓰지 않습니다.
