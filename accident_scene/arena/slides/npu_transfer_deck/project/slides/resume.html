중단을 다룬 원칙

판정이 끝난 회차는 하나도 버리지 않았다

끊긴 생성만 다시

답이 오지 않은 요청만 같은 대화 상태에서 다시 보냈다. T3 4개는 저장된 요청·응답·결과로 대화를 재구성했고, 재구성한 요청이 실제 요청과 메시지 목록 전체에서 같음을 확인했다.

옛 코드 실행의 상태 재구성

T2 a0·a2는 상태를 저장하기 전 코드로 돌던 실행이다. 1회차에 도구를 쓰지 않아 대화가 저장 파일만으로 정해진다. 지시문·첫 메시지 해시, 응답 원문, 결과 수치, 작업 폴더를 대조한 뒤 2회차부터 이었다.

판정 전이던 둘은 처음부터

T3 a1(요청 제한 초과)과 T2 a1(1회차 도중 끊김)은 판정된 회차가 없어 1회차부터 다시 시작했다. 부분 산출물은 _interrupted 폴더에 보관했다.

재시도 방식도 바꿨다 — 연결이 끊기면 서버가 다시 응답할 때까지 30초 간격으로 최대 12시간 기다렸다가 같은 요청을 보낸다. 가짜 서버(연결 끊김 → 503 → 정상)로 시험해 통과했다.
