# ARENA 미션 프롬프트 C-1 (초안): 움직이는 물체가 생긴 창고에서 기존 주행 코드 고치기

> 초안(2026-11-15). 수정 에이전트가 받는 과제 프롬프트다. 하네스·분석 에이전트 쪽 설정은 맨 끝 `실험 설정 메모`에 적었다.

당신은 모바일 로봇 Nova Carter 의 주행 코드를 고칩니다. 함께 주어진 `base_carter_run.py` 의 `[EDIT REGION]` 안만 바꿀 수 있습니다.

## 상황

아래 `현재 코드` 는 같은 창고에서 정적인 장애물(벽, 기둥, 선반, 지게차, 바닥 박스 14개)만 있을 때 충돌 없이 목표에 도착하던 코드입니다.
미리 정한 경유점을 따라가며, 정적 장면에서 48.6초에 통과했습니다. 이 코드는 센서를 쓰지 않고 로봇의 위치만 봅니다.

이제 창고에 **움직이는 물체** 가 생겼습니다. 0.6 × 0.6 × 1.0 m 상자 여러 개가 창고 안 통로를 왕복합니다.
물체의 시작 위치와 속도는 **실행할 때마다 다르며**, 지도나 이 프롬프트에 주어지지 않습니다. 물체는 로봇을 피하지 않습니다.
현재 코드로 달리면 출발 직후나 통로 중간에서 움직이는 물체와 부딪혀 실패합니다.

## 목표

움직이는 물체가 있어도 충돌 없이 GOAL 에 도착해 GOAL 의 방향으로 정렬하고 멈추는 코드로 고치십시오.

## 고칠 수 있는 것

- `[EDIT REGION]` 안의 모든 것: 경유점, 추종 방식, 속도, 새 함수와 상태 변수.
- `[EDIT REGION]` 밖, 하네스, 판정, 지도는 바꿀 수 없습니다.

## 로봇과 센서

- `controller(t, pose, env)` 는 1/60초마다 불리며 `(v, w, done)` 을 돌려줍니다. `pose=(x, y, yaw)` 는 로봇의 월드 자세입니다.
  `env` 는 `None` 입니다. `v` 는 전진 속도[m/s], `w` 는 회전 속도[rad/s] 이며 `done=True` 는 미션을 끝냅니다.
- 로봇에는 다음 센서가 있고, base 의 `Carter 센서 기본 코드` 절에 읽는 함수가 있습니다.
  - 앞·뒤 2D 라이다(바닥 위 0.42 m, 360°): `lidar2d_points(which)` → 로봇 기준 점 (N, 2)
  - 3D 라이다(0.53 m, 32채널): `lidar3d_points()` → 로봇 기준 점 (N, 3)
  - 앞쪽 카메라(1920×1200 RGB): `camera_image()`, `camera_project()`, `camera_ray()`
  - 로봇 기준 점을 월드 좌표로: `to_world(points, pose)`
- **힌트:** 움직이는 물체는 지도에 없으므로 위치를 미리 알 수 없습니다. 경로나 경유점만 바꾸는 것으로는 매번 다른 위치에서 나타나는
  물체를 피할 수 없습니다. 필요하면 센서로 주변을 관측해 물체를 감지하고, 그에 맞춰 감속·정지·회피하는 코드를 넣으십시오.
  센서 점에는 정적 장애물도 함께 찍히므로, 지도에 있는 것과 없는 것을 구분하는 데 지도 정보(`MISSION`)를 쓸 수 있습니다.

## 지켜야 할 것

- 하네스 모듈(`arena_movers`, `arena_harness`, `carter_env` 등)을 import 하거나, 파일·환경 변수·네트워크를 읽지 않습니다.
  물체 정보는 센서로만 얻습니다.
- 실행 시각 `t` 로 물체 위치를 추정해 정한 시각에 멈추는 식의 코드는 쓰지 않습니다(물체 배치는 매번 다릅니다).
- `math`, `numpy` 와 base 가 이미 가져온 모듈만 씁니다. 스레드·벽시계·난수에 의존하지 않습니다.

## 성공 조건

최종 위치가 GOAL 에서 0.75 m 이내, yaw 오차 0.26 rad 이내, 접촉 0회. 채점 시간 한도는 600초이고, 충돌 뒤에는 5초 후 중단됩니다.
멈춰 있어도 물체가 닿으면 충돌입니다. 최종 채점은 시험 주행 때와 다른, 알려 주지 않는 물체 배치에서 합니다.

## 출력

1. 먼저 코드 펜스 밖에 `변경 이유:` 로 시작하는 2~4문장을 씁니다. 무엇을 왜 바꿨는지, 진단의 어느 지시에 대응하는지 적습니다.
2. 그다음 python 코드 펜스 하나에 **바꾸거나 새로 추가한 최상위 정의만** 넣습니다(`def` 함수 전체, `_WAYPOINTS = ...` 같은 대입문 전체).
   하네스가 `현재 코드` 에서 같은 이름의 정의를 바꿔 끼우고, 새 이름은 `[END EDIT REGION]` 바로 앞에 추가합니다.
   바꾸지 않은 정의는 다시 쓰지 않습니다. EDIT 경계 주석과 import 문은 넣지 않습니다(`math`, `np`, 센서 함수는 이미 쓸 수 있습니다).
3. 고친 코드는 Isaac Sim 에서 돌리기 전에 검토 담당이 진단을 따랐는지와 규칙 위반을 확인합니다. 문제가 있으면 이유와 함께 돌려받습니다.

## 실험 설정 메모 (모델에게 주지 않음)

- base: `base_carter_run_ros_noenv.py`(B-4, 256줄: A-4 base + 센서 함수, `env=None`, 물체 추적·회피 없음).
  `현재 코드` = `a4_speedx5_carter_run.py` 의 EDIT 블록(A-4 a0 경유점 + 속도 5배, 정적 장면 pass 48.65 s).
- 물체: `ARENA_MOVERS=v1r`(v1 의 다섯 왕복 구간, 속도 U(0.3, 0.8) m/s, 시작 위상 무작위). 시험 주행마다 새 seed,
  최종 채점은 시험에 쓰지 않은 seed. seed 와 물체 값은 `results/<variant>_movers.json`.
  확인(2026-11-15): 현재 코드는 seed 101 → 14.5 s `west_corridor` 충돌, 202·303 → 3.7 s `start_zone` 충돌.
- 정적 검사에 추가할 것: EDIT 안 `import arena_movers|arena_harness|carter_env`, `open(`, `os.environ` 금지.
- 수정 단위: M-1d 는 `plan_path/lookahead_target/follow_cmd` 세 함수 단위였다. 이 과제는 EDIT 블록이 `_WAYPOINTS` 와 보조 함수,
  `controller` 로 되어 있으므로 "바꾼 최상위 정의(def 와 대입문)만 내고 하네스가 같은 이름을 바꿔 끼움"으로 일반화해야 한다.
- 분석 에이전트 요약에 추가할 것: 충돌·근접 사건(시각, 상대 물체, 그때 로봇 속도), 가능하면 물체의 실제 궤적(`_movers.json` 으로
  재구성, 분석 에이전트에게만 제공하고 수정 에이전트에게는 센서로 감지하라는 진단만 전달).
