# Level 3 — 고정 프롬프트 (로컬 LLM 벤치마크 입력)

## 사용 방법 (채점자용 — 이 섹션은 모델에게 입력하지 않습니다)

모델에게는 아래 **프롬프트 본문**과 `base_carter_run.py` **전문**만 입력하고, 수정된
`[EDIT REGION]` 블록**만** 출력받습니다. 파일 생성·실행·채점을 모델에게 시키지 마십시오
— 절차 실패가 제어 능력 측정을 오염시킵니다. 저장소를 열어 주는 에이전트식 입력
("이 PROMPT.md를 읽고 작업 수행해줘")도 금지합니다 — 이 채점자용 섹션까지 읽고 파일
생성·실행을 시도하다 무너지고, 같은 폴더의 정답 파일(solution/prompted)을 읽어
블라인드가 깨집니다. 에이전트형 CLI 에 붙여넣을 때는 입력 맨 앞에 "파일을 만들거나
실행하지 말고, 수정된 블록만 출력해줘." 한 줄을 덧붙입니다.

저장소 루트에서:

```bash
# 1) 모델 입력 생성 (프롬프트 본문 + base 전문)
{ sed -n '/^## 프롬프트 본문/,$p' levels/level3/PROMPT.md | tail -n +2; \
  echo; echo '--- base_carter_run.py 전문 ---'; cat levels/level3/base_carter_run.py; } > input.txt

# 2) 모델 출력 블록을 block.txt 로 저장해 채점 (이식 → 규칙검사 → Isaac 실측 → 판정, PASS=exit 0)
python3 levels/common/grade_block.py 3 <모델이름> block.txt
```

블록에 마커 줄·코드펜스가 섞여 있어도 grade_block.py 가 정리해 base 사본에 이식하고,
`levels/level3/results/<모델이름>_result.json` 의 `verdict` 로 판정합니다.

이 저장소의 기준 구현: [`prompted_carter_run.py`](prompted_carter_run.py) —
아래 프롬프트만 보고 작성했고 PASS 실측됨 (`results/prompted_result.json`).

## 프롬프트 본문 (여기부터 모델 입력, base_carter_run.py 전문을 뒤에 붙입니다)

당신은 모바일 로봇 제어 코드를 작성하는 엔지니어입니다. 아래에 Isaac Sim에서 Nova Carter
로봇을 구동하는 파이썬 러너 파일 `base_carter_run.py` 전문이 주어집니다. 이 파일의
`[EDIT REGION]` ~ `[END EDIT REGION]` 블록**만** 수정해서 미션을 통과시키십시오.

이 파일의 `[EDIT REGION]`에는 **이미 장애물 회피가 되는 컨트롤러가 들어 있습니다**
(레벨 2 통과 코드). 하지만 지금 설정 그대로 돌리면 목표에는 도달하되 **시간 예산을
초과해서 실패**합니다.

규칙:
1. `[EDIT REGION]` 블록 밖은 한 글자도 바꾸지 마십시오 (상단 givens, 하단 하네스 포함).
2. `controller(t, pose, env) -> (v, w, done)` 계약을 지키십시오. 매 스텝(1/60 s) 호출되며
   `pose`는 (x, y, yaw) 실측 월드 좌표, `v`는 전진 속도 [m/s], `w`는 yaw 각속도 [rad/s],
   `done=True`면 미션 종료 후 채점됩니다.
3. 센서: `env.raycast_scan()` — 현재 헤딩 기준 전방 180°를 61빔으로 훑는 평면 레이 팬.
   `[(헤딩 기준 방위각 rad, 히트 거리 m), ...]` 를 반환하며 거리가 max_range(6.0)면 그
   방위는 비어 있다는 뜻입니다. 기존 코드가 이 스캔을 사용합니다.
4. import 추가 금지 — 이미 import 된 `math` 만 사용하십시오.
5. 난수·벽시계에 의존하지 말고 `pose`·스캔 기반의 결정론적 제어를 유지하십시오.
6. 기존 코드 구조를 존중해 **필요한 최소 수정만** 가하십시오.
7. 최종 출력은 수정된 `[EDIT REGION]` 블록 전체(마커 주석 포함)만 제시하십시오.

미션(레벨 3): 시작·목표·정렬 조건은 레벨 2와 같습니다. 차이는 두 가지입니다 —
(1) 박스가 **목표 직전 (-6.2, 3.5)** 으로 이동해 우회 후 복귀 구간이 짧아졌고,
(2) **목표 반경 최초 진입 시각이 12.0 s 이내**여야 합니다 (max_time_to_goal 오라클).
현재 코드의 보수적인 속도로는 약 15 s가 걸려 이 예산을 넘깁니다.

성공 조건: 최종 위치가 목표에서 0.75 m 이내 그리고 |yaw 오차| ≤ 0.26 rad, 충돌 0회,
**목표 최초 진입 ≤ 12.0 s**, 제한 시간 120 s.

접근 지침: 회피 알고리즘 자체는 검증되어 있으니 건드리지 말고, **속도 예산을 재배분**하십시오
— 순항 속도, 회피 중 속도, 회전 속도 상한이 후보입니다. 단 너무 공격적이면 박스 모서리를
긁거나 도착 정렬이 흔들리니, 충돌 마진(막힌 각도 계산)은 유지한 채 속도 계열 상수만
올려 12 s 예산 안에 최초 진입하도록 하십시오.
